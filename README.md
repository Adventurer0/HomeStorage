# HomeStorage · 家中有序

手机、电脑都能打开的家庭收纳网页。物品放在哪里、何时存入、还能放多久，以及每次取出和移动，都记录在自己的 NAS 上。

**飞牛 NAS 用户：** 下载完整项目 ZIP 后，使用 [飞牛部署说明](飞牛部署说明.md) 中的 `docker-compose.fnos.yml`，填写访问密码即可在飞牛 Compose 界面构建启动，无需命令行。

接手开发或维护部署，请阅读 [交接文档](交接文档.md)，其中整理了项目结构、数据备份、AI 权限、更新发布和 NAS 排障步骤。

功能包含：

- **存储地图**：家 → 房间 → 货架 → 层板 / 抽屉 → 箱子，可自定义层级。
- **位置二维码**：打印贴在箱子上，用手机相机扫描后查看该位置与下级位置的物品，也可直接录入。
- **物品档案**：名称、分类、照片、数量、单位、品牌型号、标签、购买和存入日期、价格、备注。
- **自动物品图标**：没有照片时，根据物品名称和分类显示内置图标及配色；支持离线显示，上传自己的照片后优先使用照片。
- **搜索与筛选**：按名称、品牌、型号、标签、备注查找，按位置、分类和状态筛选。
- **浏览与排序**：卡片和紧凑列表切换，按最近登记、名称、数量或到期日排序；大量物品分批显示。
- **快捷概览**：点击首页统计卡片即可查看全部物品、收纳空间、正在使用的物品和到期提醒。
- **简洁界面与动效**：浅灰与系统蓝、半透明导航，页面、弹窗和新消息轻柔入场；支持系统「减少动态效果」，不打断填写和保存。
- **存取和移库**：取出、归还、借出、移库、补充、消耗、丢弃、丢失；变动与日志一起保存。
- **保质期**：每件物品设置到期日和提前提醒天数，安全绿色、临期黄色、过期红色；首页和临期页自动汇总。
- **操作记录**：查看全屋操作、单件物品历史和搜索记录。
- **数据导出**：导出 JSON 档案；完整备份包含数据库与照片。
- **自定义分类**：新增、重命名、排序和停用分类，已有物品使用稳定分类 ID。
- **归档与恢复**：保留物品数量、照片、位置和日志，将归档物品从日常库存及提醒中隐藏。
- **AI 收纳助手**：在首页通过文字或录音查找物品、生成录入、补充、移库和归档草稿；用户明确确认后才执行数据写入。
- **网页更新设置**：检查新版本、确认立即更新，或自主开启每天定时自动更新；更新前备份，失败时恢复。
- **更新下载代理**：在网页填写更新专用 HTTP / SOCKS5 代理及可选认证，帮助 NAS 通过可访问的代理连接 GitHub。

数据库为空时只有一个「家」位置，不会把示例物品混进你的库存。先添加房间和箱子，再开始录入。

网页适配手机和电脑，手机顶部提供退出登录入口。物品列表首次显示最多 48 条，点击列表底部按钮继续查看；筛选、排序和数据导出仍使用全部匹配记录。位置较多时使用缓存路径和汇总计数，减少重复计算。

界面使用本机系统字体，无需下载字体或额外安装前端依赖。入场效果以淡入、位移和轻微缩放为主；后台刷新、更新状态轮询和正在填写的表单不会反复播放动画。系统开启「减少动态效果」或浏览器不支持动画 API 时，所有内容保持正常显示与操作。

## AI 与语音设置

AI 功能可选。登录网页，进入 **设置 → AI 与语音**，填写 API 地址、密钥和模型，点击「保存配置」即可生效，**无需修改文件、重启或重建容器**。首页助手也提供进入设置的入口。

| 配置 | 用途 |
| --- | --- |
| 聊天 API 地址 | 供应商的 OpenAI 兼容 API 根地址，通常以 `/v1` 结尾 |
| 聊天 API 密钥 | 供应商提供的 API 密钥，只在 NAS 后端使用 |
| 聊天模型 | 供应商支持工具调用的聊天模型名称 |
| 语音识别模型 | 可选；支持 OpenAI 语音接口时可使用 `whisper-1`，留空关闭网页录音 |
| 独立语音 API 地址 / 密钥 | 可选独立语音服务；地址留空、未配置独立密钥时使用聊天服务配置 |

保存后的配置存放在 NAS 的 SQLite 数据库中，重启、重新部署和网页更新后保留。密钥保存后只显示「已配置」，不会回传到网页；密钥输入留空表示保留原值，需要删除时使用页面的清除选项后保存。删除独立语音密钥后会使用聊天密钥。完整数据备份包含配置和密钥，物品 JSON 导出不包含配置和密钥。

旧版本的 `AI_API_BASE_URL`、`AI_API_KEY`、`AI_MODEL`、`AI_TRANSCRIPTION_MODEL`、`AI_TRANSCRIPTION_BASE_URL` 和 `AI_TRANSCRIPTION_API_KEY` 环境变量仍兼容。首次网页保存前读取这些配置，保存后以网页配置为准，不会被旧环境变量覆盖。网页配置需要设置网页登录密码。没有填写 API 密钥时，分类、搜索、归档等普通功能照常工作。不同服务商不一定提供语音识别接口，聊天和语音服务可以分别配置。

首页可问“扭力扳手在哪里”，或说“新增两条 USB-C 线，放在书房配件箱”。AI 查询真实库存；位置不明确时需要补充信息。新增、补充、移动和归档都显示待确认卡片，用户点击确认后才能写入。草稿15分钟过期；库存或目标位置发生变化时需要重新生成。取消、重复确认不会产生重复库存。归档保留原始状态和数量，恢复后可继续使用。

AI 只获得列举分类、位置、查询物品与提出数据操作草稿的工具。没有 SQL、文件、终端、代码、Docker 或 GitHub 操作工具。用户确认由后端校验，模型不能自行确认。API 调用会将当前聊天和查询所需的少量物品信息发送给配置的服务商；不自动发送全库和照片。聊天模型返回的文字只作为建议展示，保存结果以待确认卡片和系统日志为准。

手机网页录音通常需要 **HTTPS**。通过飞牛 HTTPS 反向代理访问后允许麦克风，录音转成文字后可以先修改再发送，录音文件不持久保存。在普通 `http://NAS-IP:8080` 页面，可以用手机键盘自带的语音输入转成文字聊天。第一版未接入手机后台推送和离线语音识别。

## 在 NAS 上部署

需要 NAS 支持 Docker / Container Manager 和 Docker Compose v2。项目包含 FastAPI + SQLite 网页容器，以及独立的更新服务，没有独立数据库服务和 Node.js 构建步骤。两个服务首次共用一个本地构建镜像，后续网页容器从 GitHub Release 的校验镜像包更新，无需登录镜像仓库。支持常见的 x86_64 / ARM64 NAS。

将仓库放在 NAS 的本地磁盘，例如 `/volume1/docker/HomeStorage`。SQLite 数据目录应位于 NAS **本地文件系统**，不要通过 SMB/NFS 共享挂载另一个设备的目录。

### 一键部署

整个项目复制到 NAS 后，在项目目录运行：

```bash
sh deploy.sh
```

脚本使用 `docker-compose.yml`，首次自动创建 `.env` 并生成随机访问密码、创建 data 目录、构建镜像并等待服务健康。访问密码保存在 `.env` 的 `HOME_STORAGE_PASSWORD` 一行。重复运行会保留已有配置和数据。若 NAS 要求管理员权限访问 Docker，使用 `sudo sh deploy.sh`；应用仍以非 root 用户运行。需要 Docker Compose v2.18 或更新版本。

该 Compose 使用 `build: .` 从当前项目构建，因此需要整个项目，不能只上传一个 YAML 文件。`compose.yaml` 保留用于兼容先前的部署方式，两份 Compose 当前内容一致。

### 手动部署 / Container Manager

在该目录执行：

```bash
cp .env.example .env
```

编辑 `.env`：设置自己的 `HOME_STORAGE_PASSWORD`；通过 `id -u`、`id -g` 查询运行用户，把编号填入 `PUID`、`PGID`。端口冲突时修改 `HOME_STORAGE_PORT`。

```bash
mkdir -p data
# 用 .env 中填写的用户/组编号替换下面的 1000:1000。
sudo chown -R 1000:1000 data
docker compose up -d --build
docker compose ps
docker compose logs --tail=80 homestorage
```

手机连到家庭网络后，浏览器打开 `http://NAS的局域网IP:8080`，输入配置的密码。在群晖 Container Manager 中也可「项目 → 新增」选择仓库目录和 `compose.yaml`，先准备好 `.env` 与 data 权限。

宿主机 `./data` 挂载到网页容器 `/data`，保存 SQLite 数据库、照片和会话密钥。容器更新、删除或重建不会删除该目录。更新服务将同一目录挂载在 `/app-data`，仅在停止网页容器后备份或恢复；保持单个网页容器、单个服务进程访问同一个 SQLite 文件。

更新设置和最近三个成功更新的完整数据备份保存在 `homestorage_update_state` 卷中。更新服务使用 Docker socket 来替换当前 Compose 项目中标记为 HomeStorage 的网页容器，不开放宿主机端口；网页容器和 AI 均没有 Docker socket。`.env` 的 `PUID/PGID` 同时控制网页用户和更新令牌读取权限。

### 日常使用

1. 在「存储空间」创建房间、货架和箱子，给箱子设置 `A3-02` 等编号。
2. 打开位置二维码并打印；生成二维码时使用手机能访问的 NAS 地址，不要使用 localhost。
3. 在「全部物品」添加物品，或扫描位置二维码后在该位置录入；食品和药品填写到期日及提醒天数。
4. 拿走可归还的物品用「取出」，用完归还；食品、耗材使用「消耗」扣减数量。
5. 临期页面查看自动计算的提醒；过期物品处理后使用「丢弃」，操作会留在记录里。

保质期按 `APP_TIMEZONE`（默认上海时间）日期计算：到期日前大于提醒天数为绿色，进入提醒天数及到期当天为黄色，到期日之后为红色。首页和到期页在可见且没有打开表单时每分钟更新，回到网页也会更新。这里的到期日是你录入的期限，系统不会判断食品实际是否安全。提醒显示在网页内；第一版没有后台推送、邮件或手机系统通知，也不支持断网编辑。

手机浏览器可把网页添加到主屏幕。HTTPS 下的安装体验取决于浏览器；局域网 HTTP 下可使用普通网页和手机自带相机扫码。二维码使用当前访问地址，换 NAS 地址后需要重新打印。网页上传照片支持文件选择，手机支持时可调用拍照。

### 更新

打开网页 **设置 → 程序更新**：

- 点击「检查更新」查看最新版本和说明，再确认「立即更新」。
- 「自动更新」默认关闭。开启后每天按 `APP_TIMEZONE` 的凌晨 03:00 检查并安装新版本；关闭后不会安排新的自动安装。
- 安装前完整备份数据，保留最近三个成功更新的备份；下载失败不影响当前服务，安装或健康检查失败会尝试恢复旧容器和数据。网页显示更新进度和最终结果。

更新只接受本仓库的正式新版及对应架构镜像，核对 SHA256、版本和源码提交，不执行任意命令或降级。更新设置需要登录密码，AI 不具有检查、开启或执行更新的工具。开始安装后短暂维护，页面可读取，物品写入暂时停止；已经进行中的更新需要完成或恢复，关闭自动更新不会中断它。

若仓库公开，不需要 GitHub token。若仓库私有，在 `.env` 的 `UPDATE_GITHUB_TOKEN` 填入只授予 **Adventurer0/HomeStorage → Contents: Read-only** 的细粒度 GitHub token；飞牛用户填在 updater 的 environment。该配置只给更新服务，不给网页和 AI。不要在聊天中发送 token，也不要将已填写配置提交到仓库。访问 GitHub 或下载失败时，网页会说明原因，普通收纳功能继续运行。

从 2.5.0 起，可在同一设置页填写更新专用代理，支持 `http://`、`https://`、`socks5://`、`socks5h://` 地址及单独的可选用户名/密码。这里需要 NAS 可以访问的代理 IP/主机名与端口；VPN 订阅链接不能直接使用。保存立即用于后续检查和下载，不影响 AI API。旧 updater 需要先按 [飞牛部署说明](飞牛部署说明.md#250-更新代理与服务升级) 升级一次；仅通过网页更新应用容器不能升级旧 updater。

**已有安装需要一次升级部署**：先停止整个项目并备份数据及配置，获取本次源码，将新版 Compose 中的 updater、更新状态卷和 app 标记合并到原配置，保留原数据路径、密码、端口和 AI 配置，再构建启动。后续在网页控制更新。网页更新只替换应用容器；更新服务自身及 Compose 配置变更仍需按版本说明手动处理。

**网页更新后不要对旧源码执行 `build` / `up` 或在 NAS 点击旧项目的「重新构建」**，否则会重新安装旧版本。容器普通「重启」会保留已安装版本。修改部署配置前，先下载当前已安装版本的源码，或使用该版本的镜像；不要用 environment 覆盖 `HOMESTORAGE_VERSION/HOMESTORAGE_REVISION`。

源码开发方式更新仍可使用以下命令，但应先关闭自动更新并备份，源码版本必须不低于当前已安装版本：

```bash
git pull --ff-only
docker compose up -d --build
```

### 备份和恢复

JSON 导出包含位置、物品和日志，**不包含照片，也不是完整恢复文件**。第一版没有 JSON 导入。完整备份使用 NAS 快照，或停服务后备份整个 data 目录：

```bash
docker compose stop
tar -czf "homestorage-backup-$(date +%Y%m%d-%H%M%S).tar.gz" data
docker compose start
```

如果备份命令失败，也应重新启动项目。恢复时停止整个项目，保留当前 data 副本，再解压可信备份替换 data，确认属主与 `.env` 中 `PUID/PGID` 一致，然后启动。`.env` 单独安全保存，更新状态卷也应纳入 NAS 备份。不要同时让两个网页容器对同一份数据库写入。

### 常见问题

- **无法写入数据**：检查 data 目录权限与 `PUID/PGID` 是否一致，不要把容器改成 root 来规避权限。
- **端口已占用**：修改 `.env` 的 `HOME_STORAGE_PORT`，重新执行 `docker compose up -d`。
- **手机打不开**：检查手机与 NAS 的网络连通性、NAS 防火墙和映射端口。
- **换密码**：修改 `.env` 后执行 `docker compose up -d`；不要将密码放到二维码中。
- **外网访问**：通过自己的 HTTPS 反向代理或私有网络访问。密码登录页在普通 HTTP 上不加密传输；外网访问需要 HTTPS。

HTTPS 反向代理需要保留浏览器请求的 `Host`（含非标准端口），否则同源校验会拒绝登录或保存。Nginx 配置使用 `proxy_set_header Host $http_host;`；群晖反向代理也应保留原始 Host。

如果构建网络使用自己的可信 HTTPS 代理，基础镜像可能需要该代理的 CA。可通过 BuildKit 临时注入完整的可信 CA bundle，保持 TLS 验证；普通 NAS 网络不需要此项：

```bash
docker build --secret id=pip_ca,src=/path/to/trusted-ca-bundle.pem -t homestorage:local .
docker compose up -d --no-build
```

## 本地开发和验证

Python 3.12：

```bash
python3 -m venv .venv
.venv/bin/pip install -r requirements-dev.txt
.venv/bin/python -m unittest discover -s tests -v
.venv/bin/uvicorn app.main:app --host 0.0.0.0 --port 8080 --no-proxy-headers
```

默认数据库位于 `./data`；可通过 `DATA_DIR` 覆盖。未设置 `HOME_STORAGE_PASSWORD` 时只适用于本机开发；Docker Compose 强制要求配置密码。API 契约见 [API_CONTRACT.md](API_CONTRACT.md)。`GET /health` 检查数据库连通性。

开发检查包括物品完整存取流程、层级校验、保质期边界、上传校验、身份校验、日志和持久化。NAS 实机需要按上述步骤自行部署后确认网络与目录权限。

## 发布正式更新（维护者）

修改 `app/version.py` 的 `VERSION`，同步 `Dockerfile` 的 `HOMESTORAGE_VERSION` 默认值并更新 `RELEASE_NOTES.md`，提交后创建匹配的 `vMAJOR.MINOR.PATCH` Git tag。GitHub Actions 先核对 tag、源码版本与完整提交 SHA 并运行测试，再构建 amd64 / arm64 镜像，生成 Docker-save 的 gzip 包及 `homestorage-update.json` 校验清单，最后创建新的 GitHub Release。无需 GHCR 或 Docker Hub 登录；Release 继承仓库可见性。已有同名 Release 不会被覆盖，版本/tag 不一致会拒绝发布。
