# HomeStorage 3.0.0 交接文档

交接日期：2026-10-18（Asia/Shanghai）。项目：`Adventurer0/HomeStorage`。本版目标是家庭共用库存、可确认的数据录入、可下载的完整备份，以及权限受限的 AI 和外部接口。

本文与 `docs/handover/3.0.0.md` 保持完全一致。网页设置可以查看及下载随镜像打包的本文；发布流程另外上传 `homestorage-handover-3.0.0.md`。操作说明在仓库 `FEATURES_V3.md`，飞牛部署步骤在 `飞牛部署说明.md`，历史交接保存在 `docs/handover/`。

## 采用的模型

| 场景 | 实际采用方式与边界 |
| --- | --- |
| 本次开发协作 | Codex，GPT-6 系列。平台没有提供可独立核验的具体模型变体及各子任务路由，不臆造更细型号。 |
| 首页聊天与工具调用 | 用户在网页「AI 与语音」配置的 OpenAI 兼容聊天 API 与模型；不绑定特定厂商，不把配置默认值写成已实际使用的模型。 |
| AI 全库分类整理 | 使用发起任务时保存的聊天服务配置，任务记录实际配置的 `model`；每批最多 50 件、全次最多 10000 件。须先同意发送信息，再预览与确认分类变动。 |
| 录音转文字 | 用户配置的语音识别模型；可另设 API 地址及密钥。未配置则关闭网页录音，仍可使用手机键盘语音输入。 |
| 自动图标、热力图和条码识别 | 本地规则、SQLite 统计及 BarcodeDetector / ZXing，不调用生成式模型。 |
| 验证中的 AI 服务 | 使用受控测试响应验证流程与边界。未获得用户真实供应商、密钥和模型，不声称完成真实付费模型验收。 |

现有 Compose / `.env.example` 中的 `AI_MODEL=gpt-4o-mini` 只是兼容旧配置的回退示例，不代表本次开发实际调用该模型；没有有效密钥也不会因此自动启用 AI。

普通库存、搜索、扫码、CSV 与备份不依赖 AI。首页聊天按需查询少量数据；用户主动开启全库分类时，会把待整理物品描述分批发送给其配置的服务商。照片不随分类请求上传，后端也不会把用户确认权交给模型。服务商费用、上下文能力与语音接口兼容性需由使用者确认。

## 技术与方案

### 1. 应用结构与持久化

继续使用 Python 3.12、FastAPI、SQLite 和原生 HTML/CSS/JavaScript。无需 Node.js 构建或独立数据库服务，容器运行单个网页进程。Docker Compose 包含网页 `homestorage` 和独立 `updater`。网页进程使用非 root、只读根文件系统，仅数据目录可写；只有 updater 挂载 Docker socket。

普通 Compose 将 `./data` 挂到 `/data`；飞牛专用 Compose 使用 `homestorage_data` 命名卷。数据库、上传照片及 `session.key` 必须随原挂载保留。SQLite 应在 NAS 本地文件系统，避免将活跃数据库放到 SMB/NFS 或网盘挂载目录。不要用多个网页容器或多个 worker 写同一份数据库。

本版增加的主要模块：

| 模块 | 负责内容 |
| --- | --- |
| `app/security.py` | 用户、密码哈希、服务端会话、角色检查和账号管理 |
| `app/transfer.py` | 扫码识别、确认存取、CSV 预览与事务写入 |
| `app/analytics.py` | 操作活动、搜索事件和首页热力图 |
| `app/backups.py` | SQLite 在线快照、ZIP 清单、定时任务与 WebDAV 上传 |
| `app/organize.py` | AI 分类任务、方案预览、确认与安全回档 |
| `app/integrations.py` | 可撤销只读令牌、三条库存 GET API 和 OpenAPI |
| `app/static/v3.js`、`v3.css` | 新功能界面、管理面板和活动展示 |
| `app/static/scanner.js`、`vendor/` | 本地相机扫码和固定版本解码器 |
| `scripts/check_handover.py` | 当前与归档交接一致性、版本和必需内容检查 |

### 2. 家庭账号与权限

同一个家庭共用库存。角色为 `admin`、`member`、`viewer`；管理员管理用户与系统配置，成员操作库存，只读用户查看、搜索与导出。界面隐藏无权按钮，后端仍独立校验权限。

密码使用独立随机盐的 PBKDF2-HMAC-SHA256，迭代 600000 次。会话采用随机令牌，数据库保存 HMAC 摘要，并绑定账号的会话版本；有效期 7 天，账号停用、密码或权限变化会立即撤销相关会话。保留至少一个活跃管理员；登录失败有按来源限制，继续保留同源校验。

`HOME_STORAGE_PASSWORD` 只用于首次建立 `admin`。后续密码以数据库为准，通过网页修改；环境变量不会在每次启动时覆盖账号。旧 2.x cookie 不再被接受，升级后需要重新登录。只有新空库且未配置密码时才进入本机开发模式，不会建立真实管理员，也不能管理账号或系统机密配置。已有家庭账号的数据库即使移除 `HOME_STORAGE_PASSWORD`，仍要求登录，不会退回免登录。

日志增加操作者标识。该版本是单家庭共享数据，尚未实现各成员独立库存或家庭之间的数据隔离。

### 3. 条码、二维码与 CSV

物品可保存条码并生成专属二维码，位置二维码继续有效。扫描本身只读，确认选定物品、操作和数量后才使用既有库存状态机写入。入库映射补充，出库映射消耗，取出和归还保留原来的状态语义。幂等请求号和内容摘要防止重复扣减，相同条码多个位置时由用户选择。扫描 URL 仅解析本地标识，不请求其中的域名。

相机优先使用原生 `BarcodeDetector`，兼容回退为本地固定 `@zxing/library` 0.21.3，许可证 Apache 2.0；固定包来源、SHA-512 SRI 与许可证保存在 `app/static/vendor/README.md`。运行时不需要 npm 或外部 CDN。HTTPS、相机权限和设备支持仍是前提；扫码枪与手动输入可独立使用。

CSV 最多 10 MB、5000 行；服务端生成 15 分钟有效且绑定操作人的预览，确认时重新校验并在事务内新增。必须匹配既有分类和位置，不自动创建未知值、不按输入 `id` 覆盖旧物品、不从照片 URL 下载文件。重复条码与位置组合会跳过。导出 UTF-8 BOM 并转义公式开头的文字。CSV 是数据交换，无法替代数据库、图片和配置备份。

### 4. 活动与搜索热力图

首页默认最近 90 天；后端按 `APP_TIMEZONE` 汇总日期，并填充零活动日期。物品调动计数来自已提交的操作日志，统计操作次数而非数量变化总和。搜索事件记录非空查询及去重后的命中物品；热门物品表示出现在结果中的次数，不表示点击次数。

升级前搜索日志可用于历史查询次数，但没有逐物品命中记录，无法重建旧的热门物品数据；页面对此说明。兼容汇总历史搜索日志，并避免对新事件重复计数。此模块只统计既有操作，不修改库存。

### 5. 本地备份与 OpenList/AList WebDAV

完整备份使用 SQLite 在线备份 API 生成一致数据库，再加入该快照引用的本地照片、`session.key` 及 `manifest.json`。清单记录版本、迁移、文件大小与 SHA256；生成后校验，再原子替换成正式 ZIP。缺少引用文件、无效密钥、异常链接或空间不足时失败，避免伪装为成功。

**ZIP 包含账号密码哈希、AI 和 WebDAV 配置及密钥等私密内容，且没有内置加密。** 只能存放在可信设备或私有网盘目录。SHA256 用于发现损坏，不防止攻击者同时替换文件和清单。不包含未引用照片、既有备份文件、Compose、`.env` 或 updater 状态，应另行保管部署配置与更新状态卷。

用户已选择 OpenList/AList 的 WebDAV。HomeStorage 保存 WebDAV 目录 URL 与独立用户名/密码，按 HTTP(S) WebDAV 建目录与流式上传 ZIP；不追随远程重定向，错误信息不回显凭据。常见路径为 `https://服务地址/dav/备份目录/`，具体取决于 OpenList/AList 配置。它负责登录和挂载夸克等网盘，HomeStorage 不直接处理网盘账号、扫码登录与凭据续期。

自动备份和自动上传默认关闭。默认每日 03:30、保留本地 7 份，可在网页改时间和保留 1–30 份。时间使用 `APP_TIMEZONE`；离线错过时点不会补跑，启动时不会自动重复执行中断的上传。上传失败保留本地文件，允许手动重试。保留份数只管理本地列表，不保证清理云端历史文件。配置保存不等于远端可写，须手动上传验收。

### 6. AI 分类整理：同意、预览、确认和回档

管理员明确同意后才发起模型请求；默认处理未归档物品，可以选择包含归档物品。按每批 50 件、最多 10000 件生成分类建议，任务持久保存状态与实际模型名称。没有可用模型时提示先配置，不伪造整理结果。服务重启后中断任务显示中断，不自动重复调用付费模型。

模型只能返回受约束的物品 ID、分类名称与理由；不能发 SQL、操作文件、执行代码或替用户确认。程序校验每批 ID 完整唯一、分类字段和范围，再保存方案。预览有效期 24 小时，生成和预览阶段不变更库存。

用户再次确认时，在写入事务中比对生成时完整物品与分类快照；任何相关变动都会拒绝整批应用。应用仅更新分类引用和更新时间，保存前后版本与日志；不改数量、位置、照片或归档状态。

回档先预览，必须满足应用后物品未被继续修改。发现任何冲突就阻止整个批次，不提供强制覆盖或部分回档，避免丢失后来家人录入的信息。无冲突才在一个事务中恢复原分类。新建分类和历史日志会保留，便于追溯；回档不是删除审计轨迹，也不是完整数据库还原。

原有首页 AI 录入、移库和归档仍用待确认草稿，模型没有管理员、Docker、GitHub、文件或代码权限。

### 7. 其他 AI 的只读 API

管理员可创建家庭级只读令牌，随机 256 位凭据，数据库只存 SHA256，明文创建时仅显示一次；默认 90 天、最多 366 天，可即时撤销。前端提供可复制地址、示例及 OpenAPI 描述。

令牌只认证以下三个 GET：

```text
/api/external/v1/items
/api/external/v1/locations
/api/external/v1/categories
```

物品查询支持 `q`、`limit`、`offset`，每页最多 100 条。只返回指定库存字段，包含位置、条码、备注及价格，不含用户、配置密钥、原始数据库和照片文件；没有任意 SQL 或写入接口。普通管理路由不接受这个令牌代替登录。

**令牌属于家庭，停用创建账号不会自动撤销令牌。** 人员离开或 AI 工具停用时需在管理页单独撤销。用户把哪些库存信息发送给第三方 AI，由用户选择并负责授权。外部客户端还必须实际能连到 NAS，可使用局域网、自己的 VPN 或 HTTPS 反向代理；该功能不会开放公网端口或自动适配所有 AI 产品。

### 8. 更新与每版交接

保留原网页更新开关和确认安装机制。程序自动更新默认关闭，按 `APP_TIMEZONE` 每日 03:00 检查；备份计划是独立设置，不要混淆。更新专用 HTTP/HTTPS/SOCKS5 代理仍只作用于 updater，临时网络故障最多三次尝试，继续校验来源、TLS、SHA256、版本和架构。

每次发布需同步版本号、Dockerfile 默认版本、发布说明、当前交接与同名版本归档，运行 `python scripts/check_handover.py`。CI 验证版本对应、两份交接一致及本文五个必需主题。它能阻止漏文档，不能代替人工核对内容真实性。

Release 更新所需三个资产仍为：

```text
homestorage-update.json
homestorage-3.0.0-linux-amd64.tar.gz
homestorage-3.0.0-linux-arm64.tar.gz
```

另附 `homestorage-handover-3.0.0.md`，总计四个预期资产。更新清单继续校验镜像包；额外交接附件不改变旧客户端的必需资产协议。仅推送源码或 tag 不等于 Release 完成，网页更新须等清单和对应架构镜像实际可下载。

## 升级与回档

### 从 2.x 升级

1. 记录现有版本、Compose 项目名、原数据路径或卷名、端口和更新状态卷；备份原数据、Compose 与 `.env`，不要删除项目或数据卷。
2. 获取 3.0.0 源码或对应正式 Release 镜像。已有可用 updater 可在镜像资产完成后确认网页更新；源码构建要保留自己的配置与原挂载，不用 ZIP 里的空白密码模板覆盖它。
3. 旧于 2.5.0 的 updater 如需获得代理与网络修复，必须同时升级 updater；网页更新应用不会替换旧更新服务。完整操作见 `飞牛部署说明.md` 的历史代理升级章节。
4. 启动后执行增量迁移，保留原物品、位置、照片、分类和 AI 配置。旧 cookie 失效，使用 `admin` 与原部署密码重新登录；随后在网页创建家人账号和修改个人密码。
5. 验收原库存与照片，再试一次扫码、CSV 预览、备份下载。配置真实 WebDAV 后手动上传成功，再决定是否打开自动备份。AI 分类先用少量测试物品或隔离副本，核对预览、取消、确认和回档。

网页更新后，不能从 NAS 保留的旧源码重新构建，否则会覆盖成旧程序。普通重启保留当前镜像；以后需改部署配置，先拿到当前版本源码或对应正式镜像。

### 完整数据恢复

本版提供完整备份创建与下载，没有全库在线恢复按钮。恢复时优先使用和备份相同版本的应用及一个隔离目录，先验证再替换现有数据：

1. 确认备份来自可信来源，使用同版本 `app.backups.verify_backup(Path(备份路径))` 校验 ZIP 内路径、大小与逐文件 SHA256。不能只查看文件名或将清单当数字签名。
2. 在飞牛停止整个 Compose 项目，包含网页和 updater，避免定时任务或更新与恢复同时发生。保留当前完整数据副本和更新状态，不先删除它们。
3. 将验证后的 `homestorage.sqlite3`、`session.key`、`uploads/` 恢复到原数据挂载。保留 manifest 作为校验记录；不要混入另一个数据库遗留的 WAL/SHM。更稳妥的做法是在新的空目录恢复，再替换数据目录内容。
4. 确认原卷名或路径以及运行 UID/GID 权限正确，再启动同版本程序。验证物品数量、照片、登录、分类、配置与日志；验证通过前保留原副本。
5. 恢复旧数据库也会恢复当时账号、密码、配置及 API 令牌状态。重新核对授权，撤销不再需要的令牌；若凭据泄露，单靠恢复不能解决，应更换相应凭据。

飞牛数据卷与普通 `./data` 是不同方式，不能简单换 Compose 模板期待自动迁移。Compose、`.env`、updater 状态不在网页 ZIP 内；主机重装时须另外恢复它们。旧版程序回滚应配套恢复升级前的完整数据，不能让旧程序直接写迁移后的数据库。

### AI 分类回档

在 AI 分类批次中先查看回档预览，再明确确认。后续任何冲突会阻止整批回档；保留新数据并人工核对或重新生成方案。此机制不恢复其他日期的库存、不撤销后来的取用，也不删除新分类或历史记录。若需整库回到旧时点，应使用完整数据备份并执行上述停服恢复。

## 限制与待确认

- 家庭成员共用同一库存，不支持多家庭隔离；外部只读令牌也授予整个家庭的指定库存字段。
- 没有全库在线恢复、强行覆盖分类冲突、移动离线编辑、手机后台推送或自动识别物品照片功能。
- 相机扫码和网页麦克风依赖 HTTPS、系统权限与设备能力；HTTP 可用扫码枪、手动输入及手机键盘语音。
- CSV 只新增，不是库存同步或完整恢复，分类与位置需预先建立；照片不能通过 CSV 恢复。
- 定时备份依赖服务运行、存储空间和网盘挂载；不补跑离线时段，不保证清理云端历史文件。ZIP 无内置加密，应私密保管。
- 真实供应商的模型能力、费用、语音识别接口与 OpenList/AList 对夸克的读写仍需在用户环境验收。保存配置不等于远程连通成功。
- 目前没有实际 NAS 远程管理权限或安装完成证据；云端测试不代表 NAS 已升级。ARM64 的 CI 构建配置也不代表拥有 ARM64 NAS 实机结果。
- 仓库实际 Public/Private 状态与正式 Release 完成情况以 GitHub 页面为准。私有仓库的 updater 需仅该仓库 Contents: Read-only token，普通 API 只读令牌和 AI API 密钥不能替代它。
- 若后续发版变更了数据结构、Compose、updater 或凭据处理，必须再次写明升级、恢复、采用的模型和技术，不只更新版本号。
